# GPUI workspace refinement

The selected instance shows its Minecraft version, installed files and next action in Overview. Install review, transfer progress and retry appear there as the state changes. Settings contains profile preferences and a Files section. The Activity line remains visible while an install continues and the library stays searchable.

| Design choice | Implementation |
| --- | --- |
| Aligned surfaces | The shell keeps the reference's horizontal command header, divided library/work area, and persistent footer. Window captions use OS decoration. |
| Grayscale roles | GPUI mirrors the desktop design system's frame, surface, layer, selected, action and focus grays. Shape, weight, a selection rule, and explicit status text identify active, ready, disabled and pending states. |
| Compact actions | New instance, Import pack, Play and confirmation use intrinsic-width buttons. Workspace tabs use a short underline within the details pane. Library modes and Minecraft version choices retain their segmented controls. |
| Split and stacked library | Wide windows show the search/list and selected item together. Narrow windows open the item in one pane. Selection transfers focus away from the hidden search so Escape and Back can restore it. |
| Pack import | Ctrl+O opens the OS chooser. An owned, themed window shows the shared import review. Confirming passes the original file and review digest to the same Rust importer as Svelte, then selects the resulting profile. An import with a pending loader or descriptors shows those requirements in Overview. |

The inherited Panel shell uses one-pixel divisions and a persistent sidebar. The pinned design-system source identifies its exact commit and licensing. The desktop grayscale roles follow the sibling launcher's `design-system/workspace.css`. Windows list/details guidance supports switching between side-by-side and stacked spatial views. Windows command guidance separates app-wide from selected-content commands. Existing GPUI buttons and inputs retain their focus and keyboard behavior. An initial Windows layout used full-width accented commands. Windows review showed that stretching New instance and install across their regions competed with the navigation and made the primary action visually large. The current design keeps those actions compact. Separate pane boundaries and the selected rule preserve the structure seen in the earlier wider partitions.

The hierarchy pass gives the instance a 25 px title at wide widths and 22 px in the stacked workspace. A single task region below the tabs changes with review, cache reuse, download or ready state. The ready region keeps the play blocker in one place and gives Verify game files a quieter treatment. Installation details use aligned compact property rows. Setup diagnostics discloses the recheck, Java folder, managed JDK, client JAR and sandbox controls. The New instance form uses its native caption and pairs starting width and height.

The owner's Windows capture showed the highlighted library row meeting the highlighted Overview tab at the pane divider. Before adjusting the layout, a disposable 100-instance build repainted in desktop captures after hover, wheel scrolling, search selection, and ten narrow and wide resizes. The full-width highlights explained the visual connection in the crop.

The selected row now has space on both sides, an independent leading rail, and the same icon and text positions as other rows. The workspace tabs start at the same inset as the instance heading, action region and setup rows. An underline and stronger text mark the current tab. The fixed-width focus border keeps labels in place as keyboard focus moves. New instance and the account action remain compact in the command bar, with Play close to the instance it applies to.

The Home shelf heading is exactly **Recents** so a later switchable library can present instances or worlds without the heading choosing a data model. The heading is exposed as a native accessibility heading that introduces the list. Each Recents row keeps one 1 px Home-glass border in every state. Hover and press add a subtle grayscale fill, selection adds a single full-height 2 px leading accent rail, and keyboard focus adds one high-contrast 2 px semantic outline. The component's low-alpha focus ring remains only as a faint halo; the semantic outline is the clear cue. The row therefore has no left-plus-bottom accent frame, and selection remains distinct from hover. Pinned rows stay first and prefix their metadata with **Pinned** so truncation cannot hide the state; the selected instance remains an independent state. Rows retain the shared Button/AccessKit path: click, Enter and Space activate once, clicking does not take focus, and the action only selects the instance and opens its Library details. Focus moves into the Library detail when the row unmounts. The pointer cursor is applied to Home header and Recents call sites, not to the shared navigation action.
