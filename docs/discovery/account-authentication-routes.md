# Minecraft Java account routes

Reviewed 29 November 2026. This note covers sign-in and entitlement. Starting a protected game remains a separate capability.

## Application access and the four exchanges

Mojang says it manually reviews and allowlists new third-party integrations with the Java game-service APIs. Existing integrations can continue under their existing access. The published process gives no general exception for a fork, a self-hosted installation, or a newly registered Microsoft public client. Microsoft also requires an accurate application registration and restricts transferring credentials or assigning an application ID. [Mojang API review](https://minecrafthelp.zendesk.com/hc/en-us/articles/16254801392141-Java-Edition-Game-Service-API-Review-or-Application-Process) · [Microsoft Identity Platform terms](https://learn.microsoft.com/en-us/legal/microsoft-identity-platform/terms-of-use)

Carbon already uses the Microsoft OAuth access token to obtain an Xbox user token, exchanges it for XSTS authorization, and exchanges XSTS for a Minecraft service token. It checks Java entitlement and the current Java profile before marking the account verified. Mojang's review concerns access to game services, so changing the initial Microsoft OAuth grant does not supply that access. [Carbon device adapter](../../crates/account/src/device.rs) · [Microsoft Xbox service authentication](https://learn.microsoft.com/en-us/gaming/gdk/_content/gc/live/features/s2s-auth-calls/s2s-calls/live-title-service-calls-xbox-live)

## Supported choices

| Route | Can authenticate a Minecraft player in Carbon? | Deployment decision |
| --- | --- | --- |
| Carbon's configured public client | Yes when the registration and use have Minecraft API access and the player has Java entitlement. | Use the existing system-browser device-code flow with the configured client. |
| Operator-supplied public client | Yes under the same conditions when the operator controls the registration and Minecraft has approved it for this Carbon Desktop deployment. | Offer an explicit local configuration. A UUID's format and a successful Microsoft OAuth step establish neither Minecraft API access nor entitlement. Keep vault data scoped to the client and require sign-in under the new client when switching. The confirmation is user-supplied attestation; Carbon cannot verify ownership or approval and Mojang's approval governs actual game-service access. |
| Official Minecraft Launcher | Authentication and play take place in Mojang's launcher. | Offer this as the general fallback without asking the player to provision anything. Existing saves can be backed up and transferred through a separate user-directed workflow. |
| An existing approved third-party launcher | Authentication and play take place in that launcher under its own registration. | Users can import a compatible supported pack there and sign in there. An external pack or world transfer carries content only. |
| Carbon's cached sessions or local library | A cached session is usable only within its original client and valid entitlement policy. Local library access carries no ownership evidence. | Keep local management available. No general new-player offline sign-in or imported session. |

[Microsoft public-client guidance](https://learn.microsoft.com/en-us/azure/active-directory/develop/msal-client-applications) · [Token handling](https://learn.microsoft.com/en-us/security/zero-trust/develop/token-management) · [Minecraft Launcher install](https://help.minecraft.net/hc/en-us/articles/23907917790093) · [Minecraft installations](https://help.minecraft.net/hc/en-us/articles/360034754852-Changing-game-versions-) · [Prism pack import](https://prismlauncher.org/wiki/getting-started/download-modpacks/)

Prism documents a user-configurable Microsoft client ID. It demonstrates an interface pattern. Use a registration that identifies this deployment and carries the relevant access. A public client ID is distinct from a client secret, account token or password. [Prism API settings](https://prismlauncher.org/wiki/help-pages/apis/) · [Microsoft public-client guidance](https://learn.microsoft.com/en-us/azure/active-directory/develop/msal-client-applications)

## Alternatives evaluated

- **System-browser authorization code with PKCE** is Microsoft's desktop recommendation. It can improve the experience after the appropriate redirect is registered and tested, with the same downstream services. The existing device-code adapter is the smallest interim implementation. [Microsoft authorization-code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow) · [Microsoft device-code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code)
- **Windows account broker** can streamline Microsoft consent on Windows. It still needs a registered client and registered redirect and grants no Minecraft service access. Microsoft Store's local license API describes the current app and its add-ons. It supplies neither a Java profile nor a Java service token for Carbon. [WAM configuration](https://learn.microsoft.com/en-us/entra/identity-platform/scenario-desktop-acquire-token-wam) · [StoreContext](https://learn.microsoft.com/en-us/uwp/api/windows.services.store.storecontext)
- **Partner integration or hosted broker** is viable only with explicit authorization for the actual app and use. The published review describes an application process, and we found no public transferable partnership or official-launcher session handoff. A hosted confidential client would still require authorization. [Mojang API review](https://minecrafthelp.zendesk.com/hc/en-us/articles/16254801392141-Java-Edition-Game-Service-API-Review-or-Application-Process) · [Microsoft Identity Platform terms](https://learn.microsoft.com/en-us/legal/microsoft-identity-platform/terms-of-use)
- **Demo or offline play** depends on the official demo or established entitlement. A local username, Microsoft login, or Xbox identity alone is insufficient evidence of a Java license. Microsoft account credentials stay in official browser or launcher flows. Borrowed application IDs and tokens from other launchers fall outside the supported design. [Minecraft accounts](https://help.minecraft.net/hc/en-us/articles/19615552270221-Accounts-Required-to-Play-Minecraft) · [Minecraft free trial](https://www.minecraft.net/en-us/free-trial) · [Minecraft EULA](https://www.minecraft.net/en-us/eula)

For an installed Windows Store Minecraft Launcher, Windows exposes a documented activation contract. The installed Store package on the review host exposes its own AUMID, an OS launcher identifier distinct from OAuth. A supported Windows activation can be a one-click external handoff. The official download page is the portable fallback. No account session or Carbon save path is passed to the external process. [Windows installed-app activation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateapplication) · [Official launcher download](https://www.minecraft.net/en-us/download)
